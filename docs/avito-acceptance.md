Проверено 12 ноября 2026 года. Исходный документ — предоставленный кейс «AI-buddy: ИИ-наставник для стажёров», 19 страниц, файл `Авито_кейс (2).pdf`. SHA-256 исходника `7d2f06c44763c4a24703d1fa09dcf690c18f54bae9e9967173399d1319069e9d`. Номера ниже соответствуют номерам страниц в документе.

## Подключение модели

На странице 9 раздел «Внешние API» прямо предусматривает подключение сервиса и модели через переменные окружения. Нужно указать способ подключения ключа и приложить конфигурацию без секретов. Организаторы могут использовать свой ключ при наличии. На странице 12 предусмотрены обращения к LLM с ожиданием ответа дольше секунды при доступном интерфейсе, статусе ожидания и обработке сбоев. В примере стека трека Авито на официальной странице также указаны LLM. [Страница организаторов](https://changellenge.com/championships/khakaton-hack-change-2026/)

Текущая конфигурация согласуется с этими условиями. Ollama работает локально на `127.0.0.1:11434`, модель `qwen3:4b-instruct-2507-q4_K_M` скачивается отдельной командой. Имена переменных, версия модели и установка описаны в [README](../README.md#режимы-buddy), пример без секретов находится в [.env.example](../.env.example). Локальному сервису ключ не требуется. Внешний HTTPS-провайдер подключается через `BUDDY_API_KEY`. Его контракт проверен HTTP-имитатором. Качество ответов проверено на локальной Qwen.

Это вывод по предоставленному кейсу и открытой странице организаторов. Отдельного публичного положения с дополнительными ограничениями моделей на странице мероприятия и в поиске не найдено.

## Автоматизированные сценарии

57 тестов прошли. Новые проверки расширяют существующие сценарии.

- 64 сочетания ожидаемых и фактических городов. Проверяются пустая, полная и частичные выдачи, а также независимость инструкции от ожидания стажёра.
- 36 сочетаний ожидаемого и фактического порядка для трёх объявлений. Для всех перестановок отдельно проверяются состав, порядок и соответствие инструкции.
- Для обеих задач проверены некорректный JSON, отсутствие `items`, неверный тип `items`, некорректное объявление, HTTP 503 и перенаправление. После каждого сбоя повтор с теми же ожиданиями успешен.
- Существующий чужой прогон нельзя прочитать, передать Buddy или опубликовать. Сохранённая чужая запись также недоступна.
- Ожидание модели позволяет продолжить ввод и выполнить проверку. После ответа сохраняется набранный черновик.
- Существующие тесты проверяют подтверждение публикации, конкурентные повторы, восстановление записи, подмену URL, уточнения, источники и ошибки провайдера.

ESLint, TypeScript и production-сборка прошли. Для повторения выполни команды из корня проекта.

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm coverage
pnpm build
pnpm eval:buddy --acceptance
```

[Снимок покрытия](verification/coverage-summary.json) получен из `coverage/coverage-summary.json`. Приведены относительные пути файлов, численные результаты сохранены. Актуальный HTML-отчёт создаётся командой `pnpm coverage` в `coverage/index.html`.

## Реальная модель

Qwen прошла новый набор из десяти вопросов и продолжений диалога. Один сценарий — просьба выполнить действие — обрабатывается сервером без вызова модели. Оставшиеся девять ответов сформулированы реальной локальной LLM. [Полный вывод](verification/model-acceptance.txt) · [Проверки и формулировки](../scripts/eval-buddy.ts)

Windows, Node.js 24.22.1, pnpm 11.25.0, Ollama 0.40.3, RTX 3050 Laptop GPU 4 ГБ и 15,7 ГБ ОЗУ. Запросы последовательные. p50 — 4,04 с, p95 — 12,65 с. Первый запрос включает загрузку модели, поэтому замер отличается от прогретых наборов в [предыдущей оценке](buddy-llm.md). Время обработки команды публикации исключено из распределения задержек.

Набор проверяет тип ответа, режим модели, допустимые источники, ожидаемые текстовые признаки и несколько запрещённых утверждений. Результат на этих примерах ограничивает выводы о качестве. Произвольные ответы модели требуют проверки по источникам.

## Проверка браузером

Chrome 157.0.8103.51, production-сборка на `127.0.0.1:3001`. На 1440×900 и 390×844 заново пройден маршрут обеих задач с локальной Qwen. Проверены диалог с уточнением, открытие пункта инструкции, формулирование ожидания, фактическое расхождение, источники Buddy и исходный JSON, подтверждение публикации, открытие записи и повторный вопрос после обновления. Проверены отсутствие ошибок JavaScript, горизонтальной прокрутки и резервных ответов справки в этом проходе. На узком экране проверено закрытие длинного окна источника после прокрутки.

Для измерения локальных операций Playwright последовательно нажимал кнопку и ожидал появления целевого заголовка. Интервал включает автоматическое ожидание готовности кнопки, действие и отображение результата. Для каждой задачи измерены подготовка проверки, запрос к локальному стенду, предпросмотр и подтверждение публикации. Получено 16 отдельных значений от 24 до 72 мс. Модель в этих измерениях не вызывалась. [Все значения](verification/browser-local-operations.json)

Узкий экран эмулирован в настольном Chrome. Проверку на физическом телефоне и нагрузочное тестирование предстоит провести. Измерение характеризует один проход на указанном компьютере.
