# Сценарии демонстрации

Установите зависимости и соберите проект по [инструкции запуска](../README.md#запуск). Для разработки используйте `pnpm dev` и откройте [127.0.0.1:5173](http://127.0.0.1:5173/). Собранный интерфейс слушает порт 3001, отдельный демо-трекер — 3002. Данные локально сохраняются в `.data/buddy.sqlite` и `.data/tracker.sqlite`. Для изолированного прогона задайте `BUDDY_DB_PATH` и `TRACKER_DB_PATH`.

## Первая проверка API

1. Как **Наставник** назначьте `ACTIVE-01` стажёру А. Переключитесь на **Стажёр А** и откройте **Фильтр активных**.
2. Нажмите **Подготовить проверку**, выберите **Без фильтра** как диагностический запрос. Для основного запроса отметьте **Активные**, для контрольного — **Активные** и **Архивные**. Сохраните первый вариант.
3. Нажмите **Разобрать выбор с Buddy**. Откройте **Подсказка и доказательства**, затем **Подготовить запрос**. Убедитесь, что выбран запрос с `status=active`, и подтвердите запуск.
4. Введите «Фильтр status=active работает правильно» и нажмите **Разобрать результат с Buddy**. Откройте ссылку на ответ. При `HTTP 200` в отфильтрованной выдаче есть архивный товар `sku-302`. Запишите наблюдение своими словами и подтвердите публикацию.
5. Откройте запись. Рядом с выводом появятся состояние доставки и квитанция `TRK-…`. Переключитесь на наставника и раскройте **Ход попытки** и **Подсказки Buddy в этой попытке**. Из записи доступны исходный ответ, повтор проверки и решение наставника.

Эти шаги работают в демо-справке. Запись сделана с локальной Qwen, паузы ожидания ответа сокращены при монтаже. [Видеодемонстрация](media/active-review.mp4)

## Версии поручения и вопросы стажёров

1. Как **Наставник** создайте поручение «Проверь индекс для ночной выгрузки», выберите проверку **Активные товары после переиндексации**. Укажите, что в ответе должны быть активные товары с уникальными ID. Сохраните, опубликуйте v1 и назначьте её стажёру А.
2. Как **Стажёр А** нажмите **Начать проверку**, отметьте **Активные** и **Все ID уникальны**, сохраните первый вариант и подтвердите запуск. Стенд возвращает `HTTP 200` и два вхождения `sku-401`. После публикации наставник может повторить проверку с исправным ответом через блок **Демо-стенд**.
3. Назначьте v1 обоим стажёрам. Для демонстрации сводки отправьте по одному вопросу к критерию из блока **Что непонятно в поручении?**. Под обеими ролями сохраните первое ожидание с **повторяющимися ID**.
4. Откройте **Понятность поручения** в редакторе наставника, обновите сводку и нажмите **Уточнить в черновике**. При подключённой модели Buddy предлагает формулировку по совпадению в первых попытках. Правку можно проверить и вставить в черновик.
5. Опубликуйте и назначьте v2 тем же людям. Под обеими ролями сохраните верное ожидание уникальных ID. После обновления сводки видно, повторилось ли расхождение у тех же участников. v1 сохраняет свой текст, вопросы и записи.

Сравнение вопросов требует двух и более стажёров, которые поработали с обеими версиями. Сопоставление расхождений использует первые сохранённые варианты по одной и той же проверке каталога.

## Остальные сценарии

| Сценарий | Какую ошибку обнаружить |
| --- | --- |
| `ARCHIVE-01` | В общей выдаче исчезли архивные товары при успешном контрольном запросе. Назначение доступно наставнику. |
| [`SORT-01`](http://127.0.0.1:3001/?task=SORT-01) | При `HTTP 200` карточка без цены стоит первой. В исправном ответе она последняя. |
| [`SEARCH-01`](http://127.0.0.1:3001/) | Без фильтра пропадает Самара. При запросе с фильтром по Казани её отсутствие ожидаемо. |

На телефоне чат доступен через кнопку **Спросить**. Стажёр открывает свои публикации через **Мои записи**. Доступ к назначению и записи другого стажёра проверяется сервером.

## Подключение модели

Запустите Ollama и загрузите модель.

```sh
ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Создайте локальный `.env` по [примеру](../.env.example) и перезапустите приложение.

```dotenv
BUDDY_BASE_URL=http://127.0.0.1:11434/v1
BUDDY_MODEL=qwen3:4b-instruct-2507-q4_K_M
BUDDY_TIMEOUT_MS=45000
```

В меню режима проверки появится **Buddy · локальная LLM**. Для совместимого удалённого провайдера задайте HTTPS-адрес и `BUDDY_API_KEY`. Приложение использует `/chat/completions` со структурированным JSON-ответом. Ключ хранится в локальном `.env`. При отказе провайдера интерфейс показывает резервную подсказку. [Протокол Ollama](https://docs.ollama.com/api/openai-compatibility) · [Модель Qwen](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M)

Без конфигурации модели доступны **Демо-справка** и **Без Buddy**. В ручном режиме можно открыть инструкцию, запустить проверку и передать результат наставнику.
